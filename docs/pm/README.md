# AIチーム運用ルール（PMキット）

カンペ先生／空港えいご物語を、複数のAIで分担して作るための運用ルール。
このフォルダは GitHub リポジトリの `docs/pm/` に置かれている（2026-11-15、コミット 77fc926）。

## 体制

| 役割 | 担当 | 仕事 |
|---|---|---|
| 最終決定 | ユーザー（キング） | 固定ルールの変更承認、完成の判断 |
| PM | おちゃ（Muse） | 指示書の維持、タスク分解、依頼文の作成、成果物の検品、決定ログの記録 |
| 企画 | ChatGPT / Grok（無料枠） | イベント案、言い回し、別案出し。**コードは書かない** |
| 台本 | Gemini（無料枠） | 会話台本の量産 |
| コード | Claude（有料） | 設計が絡む実装。クレジット消費が激しいので依頼はまとめて |
| コード補助 | Copilot | エディタ内での小さい修正・補完 |
| チェック | 作ったAIとは別のAI | 成果物の一次レビュー（自己検品の禁止） |

## 正本（どれが正しいか）

- 固定ルールと設計の正本は `kanpe-design-bible.md`（設計バイブル）。迷ったらバイブルが勝つ。
- 決まったことは `DECISIONS.md` に1行ずつ追記する。ここに書かれた決定を、担当AIが勝手に覆してはいけない。
- 現在の状態は空港ごとの状態シート（例：`STATE-nairobi.md`）に書く。物語の記憶はAIに持たせず、状態シートだけを毎回渡す。

## 依頼の作法（3点セット）

担当AIへの依頼は、必ず次の3点をセットで渡す。

1. 設計バイブルの §1「固定ルール」と §10「シーン状態シート」の様式
2. 対象空港の状態シート（現在の状態）
3. 今回のタスク（`tasks/` の依頼文）

出力形式は依頼文の中で固定する（表・JSON・箇条書きの型を指定）。自由文で返させない。

## 検品の作法

- 成果物は、作ったAIとは別のAIが一次チェックし、PMが最終確認してから取り込む。
- チェック観点：①状態シートと矛盾していないか ②固定ルールに触れていないか（日本語訳の表示、文字入力、「復習」の言葉、NPCタップ誘導がないか） ③決定ログと食い違っていないか。

## Claude（コード担当）の節約ルール

- 依頼は細切れにせず、PMが仕様を固めてからまとめて1回で渡す（手戻りが一番クレジットを食う）。
- 小さい修正は Copilot で済ませる。
- コードの一次チェックは無料枠のAIにさせ、Claude は最終確認だけ。

## 版の管理

- 指示書を変えたら、ファイル冒頭の版を上げる（例：v1.0 → v1.1）し、変更点を DECISIONS.md に残す。
- 古い版の指示で動くことが一番の事故源。担当AIには「今の版」を毎回明示する。
