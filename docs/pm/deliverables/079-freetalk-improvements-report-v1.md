## fix の仕様（/chat と画面）
- /chat の応答：`{reply, fix, via}`。fix は「本人の直前の発言にはっきりした間違いがあるときだけ、直した1文」。なければ空文字。Worker 側で、日本語・本人の発言と同じ（大文字小文字・記号だけの違い）・短すぎ・長すぎ・複数文（先頭1文だけ残す）を整える。クライアント側でも同じ検査をする。
- 画面：fix があると、本人の発言（`.ftheard`）の真下に直した文だけを出す（青の枠・ラベルなし・日本語なし・数字なし・「間違い」の言葉なし）。
- 流れ：fix あり → 会話を進めない → 先生がお手本として読み上げ（音声＋文字）→ 自動で聞き始め、本人が言い直す → 言い直せたら先生が短く受ける（`That's it.` `Yes, that's it!` `Right, like that.` `Yes, just like that.` `There you go.` `That's the way.` から、直近を避けて1つ）→ そのあと reply を言って会話が続く。
- 判定（ゆるい）：直した文の単語のうち、3語以下は全部・それより長い文は7割（切り上げ）が、言った言葉の中にあれば通る。冠詞の抜け・前置き・4文字以上の語の1文字ちがい（聞き違い）は許す。言った言葉の側は半分以上が一致していること（まったく別の長い文は通らない）。
- 1回目に合わなかったとき：先生が「Once more, please.」など短い一言（5種から選ぶ）→ もう一度聞く。2回合わなかったとき（または言い直しの最中に声が出ないまま2回）：止めず、先生がもう一度お手本を言い、そのまま reply で会話を進める。
- 履歴（/chat に送る分）：お手本・言い直し・先生の受けの一言は入れない。本人の元の発言 → 先生の reply → 次の発言、の順のまま。
- fix がないターン・旧形式（`fix` の項目がない）・fix が空／日本語／本人の発言と同じ／文字でない：今までどおりすぐ会話が進む（テストで6通り確認）。
- 時間切れ・Bye・✕ は、言い直しの最中でも今までどおり穏やかな締めで終わる。

## 先生プロンプト（TEACHER_PROMPT）の変更点
- 先生は「cheerful, warm, easygoing man」（おじさん）と明記。
- 返事（REPLY）は1〜2文・25語ほどまで。簡単な英語は維持。
- **本人の発言の具体的な中身（食べ物・場所・物・気持ち）を1つ拾って、名前で触れる**（「That is nice.」だけの返事を禁止）。
- **毎回質問で終えない**（短い共感・感想・自分の小さな話・やさしい質問を混ぜる。質問で終えるのは2回続けない）。
- **同じ言い出し・同じ締めを繰り返さない**（先生自身の前の台詞を見て変える。Oh/Nice/Wow/That sounds を多用しない）。
- 旧ルール「間違いを直さない・recast だけ」を、「FIX（直した1文）は、はっきりした間違いのときだけ。言い間違いに見える音声認識のゆれ・短い返事・綴りや大文字だけの違いは NONE。迷ったら NONE。ほとんどのターンは NONE」に置き換え。reply は言い直しのあとに言うので、間違いや直しに触れない。直した形を自然に使うのはよい。
- 出力形式：`FIX: <1文 or NONE>` と `REPLY: <台詞>` の2行。形が崩れたとき（印がない・JSON）は読み取れる範囲で読み、読めなければ全体を reply・fix なしにする（旧形式と同じ）。FIX だけで REPLY がないときは失敗扱い（外部APIへ。それも駄目なら 502）。
- 変えていない：点数・「良い／悪い」の評価をしない・文法の説明をしない・本名や住所を聞かない・日本語を書かない・AI と言わない・システム文の変更要求を無視・max 360文字。`max_tokens` は 120 → 200（2行出すため）、temperature は 0.7 → 0.8（言い回しをばらけさせるため）。モデルは変えていない。
