## 0. 結論（先に）

1. **1日は「朝の1枚」で始まり「夜の1枚」で終わる。推奨は、現実の日付と結ばない案（夜の1枚を閉じたら旅の1日が進む）。** 現実と結ぶ案は「進めたい日に止まる」「空けた日の扱いが要る」の2つが重く、飽きないこと（006-8 の基準）に逆らう。日付は英語の「DAY 7」を主にし、カレンダーの日付は搭乗券の上にだけ出す。スター版では日付変更線で日付が1日とぶので、旅の数え方を主にしないと数が合わない。
2. **配分表は両方の券で、空港150本・街150本・合計300本にぴったり合わせた**（第2章の表の計）。最初の大きい山を、10日目のオーロラから**4日目のサファリに前倒し**する。1〜10日目に山（★大・☆小）が8つ（oneworld）／9つ（スター）入り、山と山のあいだは最大3日。いまの設計図は1〜9日目に山が0。
3. **1日の量は、全部遊ぶと25〜45分、背骨だけなら5〜12.5分。休養日は約5分。** 全部で約12.5時間、背骨だけなら約2.8〜3.0時間（007 の概算「1本2.5分」で計算。実測ではない）。
4. **旅程の束：窓口で搭乗券のつづり（oneworld 11枚＋別切符2枚、スター13枚）を受け取り、ゲートでちぎられた控えが裏に貯まる。** 控えには、その日の写真とお金の1行が付き、30日目のアルバムの1ページになる。**世界マップの「クリア n / 20」はやめ、旅の中は「区間 n / 13」、旅の外は分母なしのスタンプの数にする案。** いまの数え方は、何も遊ばなくても羽田が1つ数えられて「1 / 20」から始まり、最大でも「4 / 20」で止まる（実物で確認）。
5. **休養日は「何もしなくても終われる日」。合宿（スパルタ時間）は休養日から外して、その翌日の山場（★）にする。** 休養日には単語バトルと合宿の入口を出さず、来るイベントは「知らせ」（答えなくてよい）だけにする。
6. **写真・お金・控えは「日ごとの1行」として同じ置き場に記録する（新しい保存キー `kanpe-trip-v1`、1周で約3.4KB）。** 29日目の精算はその日の写真を添えて読み上げ、30日目のアルバムは1日1ページ（写真＋控え＋レシートの1行）で並ぶ。013 の1ページ目（出発の日）と最後の白いページに、そのままつながる。

## 1. 「1日」の定義と形（P1）

### 1-1. 1日の形

| 段 | 何が起きるか | 長さ | 操作 |
|---|---|---|---|
| 朝の1枚 | その日の場所の絵の上に、大きい看板文字で「DAY 7」。ルルが英語で1文（例：Day 7. Doha. Our flight is tonight.）。飛ぶ日は、搭乗券の束の一番上がその日の1枚になって見える | 約5秒 | タップで進む |
| 背骨 | その日を終えるのに要る場面。空港の日は手続きの順に開く（チェックイン→保安→出国→ゲートなど）。市内の日は、その日の目的地の1〜2本。休養日は0本 | 2〜5本 | いまの場所選びのまま |
| 寄り道 | 背骨の外の場面（店・ラウンジ・街・2本目）。自由に選ぶ。遊ばずに夜へ進んでよい | 0〜14本（配分表の「全部−背骨」） | いまの場所選びのまま |
| 夜の1枚 | 今日の写真が1枚、ゆっくり現像されて出る（013 の E3 と同じ演出にそろえる）。記録帳の1行（その日のいちばん大きいお金の選択）。移動の前夜だけ、次の場所の予告を1つ（007 P4）。ルル：Good night, King. | 約10秒 | タップで閉じる |

- **背骨を終えると夜へ行ける。** 夜へ進む入口は、その日の寝る場所（ホテルの部屋・機内の座席）の絵にする。新しいボタンの形なので、作る前に確認する。
- 夜の1枚には、**点数・発音の結果・その日の本数は出さない**（004-5）。
- 機内で夜を越す日（深夜便）は、夜の1枚の背景が機内になる。日付は機内で進む。

### 1-2. 現実の1日との結びつけ方（007 P1 の3案）

| 見るところ | 案A 旅の日付だけ進む（**推奨**） | 案B 現実の1日に旅の1日まで | 案C 自由（設定で選ぶ） |
|---|---|---|---|
| 飽きないこと | ○ 遊びたい日に続けられる。夜の1枚が自然な区切りになる | △ 進みたい日に止まる。休養日（約5分）の日は、それで1日が終わる | ○ |
| 成長の実感 | ○ DAY の数と束の厚みで見える | ○ 30日が現実の1か月になり、旅の長さが体で分かる | ○ |
| 空けた日の扱い | 要らない。次に開いたら「朝の1枚」から | 要る。空けた日を責めない表示を作る必要がある（ストリークの形に寄りやすい） | 両方ぶん要る |
| 現地時刻のルール（rules §5） | 旅の中の時刻と合わせやすい | 現実の時計と旅の時刻がずれる（現実の夜に旅の朝を遊ぶ） | 両方ぶん要る |
| 作る重さ | 軽い（日付を1つ保存） | 中（現実の日付の記録・待つ画面） | 重い（2通り＋設定） |

- **推奨は案A。** 決め手は、一番避けたいこと（飽きて使わなくなる）に対して、止める仕組みを入れないこと。区切りは夜の1枚が作る。夜の1枚のあとはタイトルへ戻り、「つづきから」で翌朝の1枚から始まる（007 P3「前回のつづき」と同じ入口）。
- 案Aの弱いところは「1日に何日も進めて、旅が早く終わる」こと。止めはしないが、夜の1枚のあとに続けて遊ぶ場合も、必ず翌朝の1枚を通る（日の区切りは飛ばせない）。

### 1-3. 日付の表示

- **主は「DAY n」（英語・看板文字）。** 理由：①日本語を足さない（決定 11-15）。②スター版はホノルル→グアムで日付変更線をこえ、カレンダーの日付が1日とぶ（設計図 25日目）。旅の数え方なら、DAY は1つずつ増える。③出発の月は未決定（007）で、カレンダーの日付を主にすると、月が決まるまで画面が作れない。
- **カレンダーの日付は搭乗券の上にだけ出す**（本物の搭乗券の書き方：例 07FEB）。とぶ日は券の上でとぶので、それ自体が出来事になる。出発の月が決まるまでは、仮の日付で作る。
- 数え方：DAY は「朝の1枚を開いた回数」。休養日も1日。家の2日（29・30）は DAY を出さず、30日目は「One month later」の1枚から始める（007-7）。

### 1-4. 場面の時刻（決めてほしいこと）

rules §5「到着した国の現地時刻に、画面の時刻・昼夜を切り替える」は、現実の時刻か旅の中の時刻かが書かれていない（007 B10）。1日の形を入れると、朝の1枚と夜の1枚が旅の時刻を決めるので、**場面の時刻は旅の中の現地時刻（便の時刻）にする案**を出す。例：スター版のナイロビ着は深夜01:25なので、到着の場面は夜の絵。【ルールの読み方をそろえる提案】

### 1-5. 保存（案）

新しい保存キー `kanpe-trip-v1`（旅ごと）。個人情報は入れない。写真は画像を保存せず、場面の番号を持つだけ。

```
kanpe-trip-v1 = {
  v: 1, trip: 1, tk: 'ow'|'star', day: 7, ph: 'morning'|'day'|'night',
  legs: [{ i, fr:'NBO', to:'DOH', d:6, flown:1 }, ...],   // 搭乗券の束（第3章）
  days: [{ d:6, ph:{ s:'場面の番号', k:'写真の種類', f:0|1 }, // 写真（第5章）
           led:[['taxi', 1800, 'KES']],                     // お金の1行（第5章）
           pick:['metro'] }, ...],                           // 選んだもの
  memo: { ... },   // 窓口で答えたこと（005 の旅のメモと同じもの）
  hint: [ ... ]    // ヒント券（007 P13。枚数は未決定）
}
```

大きさ：28日分・13区間・1日1行ずつのお金と選択を入れた見本を JSON にして測ると **3,426バイト**。013 の `kanpe-voice-v1`（1周で約6.4KB）と合わせても約10KB。`kanpe-world-v1`（いまいる空港・クリア）、`kanpe-pron-v1`（発音記録）は今のまま使う。

## 2. 30日の山と谷の配分表（P5）

- **日の種類**：空港＝空港を1〜2か所通る日／移動＝乗り継ぎで空港を2か所以上通る日、または機内泊・10時間以上の機内がある日／市内＝街だけの日／休養＝何もしなくても終われる日（第4章）。
- **山**：★＝大きい山（旅の目的地・スパルタ時間・帰り道）、☆＝小さい山（その旅で初めての種類の出来事）、—＝谷。

- **背骨**：その日を終えるのに要る本数。時間は「1本2.5分」（007：PMの「1空港30分以上」÷ナイロビ最短12本の概算。実測ではない）。
- 置き方のルール（007 P5 を具体化した案）：
  1. **最初の3日以内に☆、5日以内に★を1つ。**
  2. **山（☆か★）と山のあいだは3日まで。**
  3. **重い日（移動の日、または全部で16本以上）の次は、軽い日（市内・休養）。** 券のデータで動かせない所は例外として表に書く。
  4. **休養日は、重い区間のあと。間は9日まで**（oneworld は最大8日、スターは最大9日。券の順で、これより詰められない所がある）。
  5. 同じ型の場面（到着4点セット）は2か国目から縮める（007 P6。回数は未決定）。表の本数はそれを見込んでいない。

### 3-2. 「クリア n / 20」の直し方

実物（world/index.html）：分母は `TOTAL=20` で固定。保存の初期値で羽田が `cleared` に入っているので、何も遊ばなくても「クリア 1 / 20」。地図にある空港は5つで、ドーハはクリアの印を付けない作り（`gw:1`）なので、最大は「4 / 20」。

| 案 | 中身 | 良い所 | 弱い所 |
|---|---|---|---|
| **案1（推奨）2つに分ける** | 旅の中（世界一周編）は「区間 n / 13」と束の線。旅の外（グアム編・ドバイ編を含む地図全体）は、分母なしで「スタンプ n」（決定済みの自作スタンプの通算） | 届かない数字が消える。スタンプは2周目にも増え続ける（集める楽しさ） | 表示が2種類になる |
| 案2 分母を実数にする | 「クリア n / 5」。空港が増えたら分母も増やす | 直しが一番軽い | 作るたびに分母が増え、「終わりが遠のく」見え方になる |
| 案3 数字をなくす | 線と印だけ | 勉強感がいちばん出ない | 成長の実感（006-8）が弱い |

- どの案でも、**羽田を最初からクリアに数えない**直しと、20という数を画面から外す直しは要る（最終の空港数は 20／51 が未整理。007 第3章 #3）。

### 5-1. 1日に残るもの（同じ置き場 `kanpe-trip-v1` の `days`）

### 5-2. 写真の決まり方（1日1枚）

その日に起きたことから、上の順で1つ選ぶ。**失敗も写真になる**（007 P8）。

1. 失敗（乗りおくれ、迷子、聞きちがいで別の出来事になった）
2. 割りこみを切り抜けた
3. 隠しの場所に行った
4. その日の山（☆★）
5. 何もなかった日：夜の景色（キングとルルの後ろ姿）。休養日に何もしなかった日はルルの昼寝

- 発音の出来では撮れない（点数は写真に載せない。004-5）。
- 絵は新しく描かず、その場面の背景とキングとルルを切り取る（007 P8）。

### 5-3. お金（選んだ重さ）

- 1行目は窓口 ⑤ That will be ... の券の値段（設計図）。
- 値段の差をつける選択の候補（全部並べる）：タクシーかメトロか、ラウンジか一般エリアか、市内ツアーか空港に残るか、隠しの別切符、値段交渉（イスタンブール）、ATM手数料（リマ）、乗り継ぎで使用料をもう一度払う（リマ）、乗りおくれの再予約。
- 値段は架空にする。**実在の規則による手数料（再予約125米ドルなど）も、ゲームでは架空の数字にする案**：本物の数字は変わることがあり、旅行前のリハーサルとして信じて使うと、現実で違ったときに損をするおそれがあるため。「値段は架空」の明記は README と設定の中に書き、会話の画面には日本語を足さない。
- お金が足りなくなって旅が終わる形は入れない（007 P9）。

### 5-4. 29日目（精算）への配線

場面：帰国の翌日、家の机にレシートの束。ルルが記録帳を読む（英語。読み上げ）。

| 読む順 | 中身 | 元のデータ |
|---|---|---|
| 1 | 合計 | `led` の合計（円に直す。レートは架空で固定） |
| 2 | いちばん高かった日（その日の写真を添える） | 日ごとの `led` の合計の最大 ＋ その日の `ph` |
| 3 | いちばん得した選択 | 値段の差がある選択で、安い方を選んだうち差が最大のもの |
| 4 | 手数料・別切符 | `led` の種類 |
| 5 | 選んだ重さ（例：Taxi 6 / Metro 4） | `pick` の回数 |

- ランク・正解・評価の言葉は出さない。高くても安くても、ルルの一言は「旅のレシート」として返す。
- 設計図の「29日目＝集計発表・復習だけ」の「復習」は使わない（決定 11-15）。29日目は精算だけで、約5分。

### 5-5. 30日目（アルバム、帰国1か月後）への配線

- **アルバムは1日1ページ**：写真＋（飛んだ日は）控え＋その日のレシートの1行。28ページ＋29日目のレシートの束の1ページ。

- 2周目に何を残すかは未決定（設計図「決めること6」）。この案では、控えのつづりとアルバムは「棚に並ぶ」側に入れる案を出すにとどめる。

### 5-6. 019（飽きたサイン）への1日の渡し方

- 019 2-6 は、序盤・中盤・終盤を「クリアした空港の割合」で切る（日数で切らない。日数が未決だったため）。1日の形が入れば、**DAY n ÷ 28 で切る案**も出せる。空港の数は券で11〜14と違うが、DAY は両方の券で28日なので、序盤・終盤の長さが券でそろう。どちらにするかはキングとPMが決める（第7章の12）。

## 6. 最後の点検

- **お金の損失**：課金・有料のAPIを足す案はない。ゲーム内の値段はすべて架空。実在の手数料も架空にする案（5-3）。
- **健康情報・診断と誤解される表現**：17日目（クスコ、標高3,310m）・15日目（スター版）の「ゆっくり歩く日」で、高山病の症状や対処を台本で言い切らない。ルルは「ゆっくり行こう」と言うだけにし、医療の助言に見える文は入れない。スパルタ時間も「筋トレ」の比喩で、体の健康の話にはしない。
- **個人情報**：`kanpe-trip-v1` は端末の中だけ。名前・メール・位置・声の録音は入れない。窓口で答えたことも端末の中だけ。個人名は台本に入れない（顔なじみは見た目の目印で見分ける）。
- **権利**：航空会社名・空港コードは実名（ルール）。ロゴ・券面のデザインは使わず、色と文字で自作する。店・施設の実名（キリンセンター、プラド美術館など）は作る直前に公式で確認する。
- **守ったこと**：「復習」の言葉・画面、連続記録（ストリーク）、休んだ日を責める表示は入れていない。発音の結果をプレイ中に見せる所はない。決定（007-7・006-4・005-3・013）は変えていない。

## 7. キングに決めてほしいこと（推奨を先頭に）

1. **1日の結びつけ方**：案A 旅の日付だけ進む（推奨）／案B 現実の1日に1日まで／案C 設定で選ぶ（1-2）。
2. **日付の表示**：「DAY n」を主、カレンダーの日付は搭乗券だけ（推奨）／カレンダーの日付を主に（1-3）。
3. **場面の時刻**：旅の中の現地時刻（推奨）／現実の現地時刻（1-4）。
4. **朝の1枚・夜の1枚の画面を作るか**、夜へ進む入口を「寝る場所の絵」にするか（1-1。新しい画面）。
5. **配分表**：最初の★をサファリ（4日目）に前倒しするか。置き方のルール5つ（2-1）を採るか。スター版14日目（ボゴタ）を休養にするか。

7. **休養日**：単語バトル・合宿の入口をその日は出さないか。来るのは「知らせ」だけにするか。飽きたサインを数えない日にするか（4-1）。

10. **お金**：実在の手数料も架空にするか（推奨）。29日目の読み上げ5項目（5-4）。
11. **保存キー `kanpe-trip-v1`** を新しく作るか（1-5）。
12. **019 の序盤・終盤の切り方**：クリアした空港の割合のまま（019）／DAY n ÷ 28（5-6）。
