# タスク048 実装報告：CAアナウンス・イベント（v1）

## 結論
最初の長距離便の終わりに、CAに頼まれて機内アナウンスを読み、食事の場面で自分の声の放送が流れる流れを組み込んだ。声は端末内だけ。外へ送るコードはない。専用テスト `tour-src/tests/test_pa048.py`（oneworld・Star両方）は NG 0件。実機（iPhone/Android）のマイクは未確認。

## 流れ
1. 羽田の機内の会話のあと、CA場面（`hnd_ev_ca_ow` / `_star`）。CAが「声の調子が悪い」と放送を頼む。ルルの反応は食事の場面側。
2. マイク画面。カンペは意味のまとまりで区切る。ボタンは おてほん／はなす → もういちど／これでOK。
3. 「これでOK」で端末内に保存。食事の場面（`hnd_ev_meal_*`）で、チャイム → 自分の声 → ルルの反応（2往復）。
4. 食事の場面の終わり、または便の終わりで声を消す。

## 声の扱い（プライバシー）
- 保存先: IndexedDB `kanpe-pa-rec-v1`（`kanpe-pron-v1` `kanpe-voice-v1` とは別）。localStorage には音声を入れない。
- `pa.js` に fetch / XHR / sendBeacon / WebSocket / Azure関連 / URL が無いことをテストで確認。
- 録る・聞く間、ページ内の通信呼び出し0件、ブラウザの要求に外部への送信0件（フォント読み込みのGETのみ別枠）。
- 確定（これでOK）まで保存しない。録り直し可。6時間たった物・再生済みの物は起動時に捨てる。1録音の上限40秒。
- マイク不許可: CAが「No problem. I will do it myself.」と引き取り、静かに先へ。MediaRecorderなし・こえをださないモードではCA場面自体を出さない。
- 画面に「録音」「テスト」「測定」などの言葉は出さない（テストで確認）。
