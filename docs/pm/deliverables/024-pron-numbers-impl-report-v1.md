# 024 発音の数字まわりの仕上げ 完了報告 v1（2026-11-18）

## 結論
終わりの場面の4つの数字を Azure の値そのものに差し替え、窓口の読み返し（win_rb）にも Azure を使い、同意文を実態に合わせて版を上げました（コミットは3つの塊＋生成ページ）。**マイクと本物の Azure は実機でしか確認できません（未確認）。** ヘッドレスは偽SDKでの確認です。

## 差し替えた計算式（前→後）
- 前（016の仮）：総合＝正確さ×0.6＋流れ×0.2＋言い切り度×0.2／正確さ＝語ごとの AccuracyScore の平均／流れ＝区切りごとの FluencyScore を長さで重みづけ／言い切り度＝紙の単語のうち対応づいた割合
- 後：総合＝PronScore／正確さ＝AccuracyScore／流れ＝FluencyScore／言い切り度＝CompletenessScore（すべて Azure が返した値）
- **注意：Azure の連続認識は「区切りごとの値」しか返さず、全体の値は返りません。** 公式ドキュメントに、複数の区切りをまとめる方法の記載はありません（Microsoft Learn「Use pronunciation assessment」）。区切りが1つならそのまま。複数なら、各区切りの Azure の値を、その区切りで聞き取れた語数で重みづけして平均しました（新しい式は入れていません）。区切りごとの元の値は記録の `sg` に残してあるので、集計のしかたを変えても測りなおしは要りません。
- 参考：Azure の総合の重みは「点の低い順に 0.6・0.2・0.2」と公開されています（読み上げ・抑揚なし）。016報告の「重みは非公開」は誤りでした。

## 記録の互換
- `kanpe-voice-v1` の形は変えていません。測定1回ごとに `calc`（数字の意味の版）と `sg`（区切りごとの値）を足しました。印のない古い記録は `calc=1` 扱い。
- 始めが古い版・終わりが新しい版のときは、数字を並べず、単語の色だけで比べます（数字の意味が違うため）。ヘッドレスで確認済み。
- plog には `src`（az／sr）と、Azure のときだけ `az=[総合,正確さ,流れ,言い切り度]` を付けました。読み返しは plog だけに残り、始めと終わりの比べ（trips）には入りません。
