## 1. 数字の差し替え（コミット 010b831）
| | 前（016 の仮） | 後（024） |
|---|---|---|
| 総合 | 正確さ×0.6＋流れ×0.2＋言い切り度×0.2 | PronScore |
| 正確さ | 単語ごとの正確さの平均 | AccuracyScore |
| 流れ | 区切りの流れを長さで平均 | FluencyScore |
| 言い切り度 | 紙の単語のうち聞き取れた割合 | CompletenessScore |

- 長い宣言は連続認識で、**Azure は区切りごとに4つの値を返し、全体で1つの値は返しません**。そのため：
  - 区切りが1つ：その4つをそのまま使う（PronScore も Azure の値）。
  - 区切りが2つ以上：区切りごとの Azure の値を合わせる。正確さ＝区切りの AccuracyScore を単語数で平均／流れ＝区切りの FluencyScore を長さで平均（Microsoft の旧サンプルと同じ考え方）／言い切り度＝紙の単語のうち「聞き取れて正確さ60以上」の割合（Microsoft の新サンプルが誤発音とする区切りと同じ）／総合＝下の公式の式を3つにあてる。
- **016 報告の訂正**：「Azure の重みは非公開」と書きましたが、Microsoft Learn に式が載っています。抑揚なしの読み上げでは、3つの値を小さい順に s0・s1・s2 として `PronScore = 0.6×s0 + 0.2×s1 + 0.2×s2`（重みは項目ではなく順位にかかる）。公開されている結果の例4件と一致しました（100/96/100→97.6、44/80/20→36.8、54/100/0→30.8、抑揚ありの 63/51/67/69.9→60.4 は手計算で 60.38）。前の仮の式は、重みの付け方が違っていました。
- 記録：`kanpe-voice-v1` の測定に `nv:2`（数字の意味の版）、`nseg`（区切りの数）、`az`（区切りごとの Azure の値）を足しました。`nv` のない古い記録は独自の式の数字なので、**数字は並べず、単語の色の比べだけ**行います。SR（ブラウザの音声認識）の経路は今までどおり数字なしです。画面の数字は整数で出します。
