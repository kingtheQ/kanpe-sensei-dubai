## 0. 結論（先に）

1. **キングの不安は当たっている。いまのルールは「1場面の中」はよく決まっているが、「30日の旅」を動かすルールがほとんどない。** 1場面の型・発音・UI・音は細かく決まっている。一方、「1日とは何か」「いま旅のどこにいるか」「選んだことがあとで何になるか」「帰国のあと次の旅へどうつながるか」を決めるルールは、資料のどこにもない（第2章の表）。
2. **一番大きい穴は「1日」の決まりがないこと。** 30日・29日目の精算・30日目のアルバムは日付で組まれているのに、ゲームの中に日付がない（画面にも保存にも0か所）。1日がどこで始まりどこで終わるかが決まらないと、ペース配分も、目標の見え方も作れない。
3. **二番目は「目標が見えない」こと。** いま見える目標は世界マップの「クリア n / 20」だけで、行ける空港は5つ（クリアの印が付くのは最大4つ）。20には届かない数字が出ている。30日のうち何日目か、券の残り区間、帰国までの遠さは見えない。
4. **三番目は「選んでも何も残らない」こと。** 選択と分岐のルールはあるが、選んだ結果が残る先（写真・お金・人との関係）のルールがない。29日目の精算と30日目のアルバムは、途中の選択が流れこむ先なので、ここが一番もったいない。
5. **30日の配分にかたよりがある（設計図の oneworld 版を数えた）。** 空港を通る日は30日のうち12日。空港の会話150本がその12日に乗るので、空港の日は1日12.5本、街だけの日は1日9.4本（概算）。最初の大きな目的地（オーロラ）は10日目で、キングが「飽きてきた」と言ったナイロビ・ドーハは2〜8日目にあたる。**序盤にごほうびがない。**
6. **遊び直しは、いまの設計だと「半分は同じ旅」になる。** 2つ目の券は会話300本のうち140本（47%）が使い回しで、大きな目的地4つ（ナイロビ・ロヴァニエミ・クスコ・ホノルル）も共通。「別の券で別ルート・別の空港」という決まりに対して、2周目で何が変わるかのルールがない。
7. **資料どうしの食いちがいは22件。** 一番急ぐのは、rules.md に残る「日本語で答え合わせ」「復習を必ず入れる」（決定ログと逆）と、空港の数（20／51／11〜13／5 が混ざっている）。
8. **足りないルールとして15個を提案した**（第2章）。軽い順に並べると、最初の5つ（前回のつづき、旅程の束、次の国の予告、2本目を遊ぶ理由、同じ型の場面の上限）は台本と小さな表示だけで入る。

## 2. 成果物2：不足しているルールの提案（15個）

候補は絞らずに並べた。重さ：**軽い**＝台本と小さな表示だけ／**中**＝仕組みを1つ足す・保存する項目が増える／**重い**＝画面や地図の作りかえ。
画面が変わるものは、作る前にキングの確認が要る（第4章）。既存の英語アプリの型（並べ替え、英単語→日本語3択、段階的にヒントを隠す仕掛け）と、「復習」につながるものは入れていない。連続日数を数えて休むと消える形（よくある学習アプリの型）も入れていない。

## 5. 数字（数え方）

- 場面の数・1か所の本数・場所の名前：tour-src/build.py の place(...) の定義を数えた（19か所。賢者3本、券選び2本、ナイロビ12か所×2本、ドーハ4か所×2本＝37本）。
- 持ち時間：tour/index.html の LIMIT=5000（単語バトル）、Meaning! の「width 5s linear」。ヘルプ：HELPMAX=5。
- 世界マップ：world/index.html の AP（5空港）、TOTAL=20、となりの空港の表。クリアの印：tour/index.html の worldSync（空港タブの場所を1回ずつ）、build.py の「ドーハはクリアの印をつけない」。
- 日付・写真・お金・スタンプの有無：5つのページで「日目」「アルバム」「スタンプ」を数えた（旅の記録としては0。アルバムの2か所はドバイ編の会話の中の言葉）。記録帳は、世界一周編の設定の中に「ルルの カバンの きろくちょう」があり、中身は選んだ券と会話の数。
- 保存の置き場：5つのページの localStorage の名前を並べた。
- 30日の配分：設計図の oneworld 版の表から、空港を通る日を数えた。会話の本数は設計図の「空港150本・街150本」を日数で割った概算。
- 1日の長さ：PMの「1空港30分以上」（STATE-nairobi）を、ナイロビの最短12本で割った概算。実測ではない。実測するなら、声を出すモードで実機で1日ぶん遊んで測る。
- 使い回しの割合：設計図の「共通140本」÷300本。

## 6. 最後の点検

- お金の損失：課金・有料のAPIを使う提案はない。ゲームの中の値段は架空と明記する（P9）。
- 健康情報・診断と誤解される表現：該当なし。
- 個人情報：個人名は入れていない。旅を通して出る相手は、見た目の目印で見分ける。写真と旅のメモは端末の中だけに置く前提。
- 権利：新しく実在の作品・ロゴを使う提案はない。スタンプは決定どおり自作。
- 守ること：決定を変える所は【ルール変更の提案】またはバイブル・設計図の「案をせばめる」と書いた。未決定の数字（発火確率、回数、日数、枚数、先に作る券、5,000語の配り方、出発の月）は決めていない。既存の英語アプリの型と「復習」につながる提案は入れていない。
