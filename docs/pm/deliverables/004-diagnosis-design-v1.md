## 0. 結論（先に）

1. **置き場所は「窓口で2回、はさむ」を推す。** 聞き取りの前に「夢を言う」（案A）、買う直前に「読み上げ確認」（案C）。賢者の「旅立ちの誓い」（案B）は代わりの置き場所。
2. **2回に分ける理由は、誤認識との切り分け。** 同じ音が、別の場面・別の単語で2回とも崩れたら「発音」、1回だけなら「たまたま（マイク・タイミング）」と扱える。1回の長い文だけでは、この切り分けができない。
3. **文は3セット作り、音を数えた。** 各59〜76語。英語の39音のうち35〜36音を含む。狙った音（TH・F・V・語尾のL・R・æ など）は、ほぼすべて「別々の単語3つ以上」に入れた（表は第2章）。
4. **今の冒頭は、弱点を測る材料として足りない（実測）。** いまキングが言う文（sage_1〜3＋ticket_star、105語）には **V の音が1語もなく、TH は thank の1語だけ**。今の会話のままでは、VとTHの弱さは見えない。
5. **集計は「音ごとの機会と失敗」を数える1つの形にして、方式①（ブラウザの音声認識）と方式②（Azure）のどちらの結果も同じ表に入れる。** 単語の出し分けは辞書の音タグの絞り込みだけで、実行時のAIは使わない。
6. **精度はまだ分からない。** この案で言えるのは「文に何の音が入っているか」まで。方式①でどこまで当たるかは、試作で本人の自覚と比べるまで未検証（第3章の末尾に、分かること・推定・未確認を分けて書いた）。

## 1. 成果物1：埋め込み設計（場面案3つ）

### 共通の形（3案とも同じ）

- 画面は1枚。文は「ルルのメモ」「誓いの巻物」「券の控え」など、**その世界にある紙**として見せる（カンペを出す理由を、UIの都合でなく世界の物にする。バイブル§1）。
- プレイヤーは、その紙を最初から最後まで続けて言う。**1文ごとの合否・％・青字・「ブッ」の音は出さない。** 言い終えたら、相手が中身に返事をして物語が進む。途中で詰まっても進む。

## 2. 成果物2：診断用の文（3セット）と音の表

### 数え方

- 発音は tour-src/ipa.py と同じ CMU Pronouncing Dictionary（cmudict）。同じつづりで読みが2つある語は手で指定した（read は /riːd/）。
- 「語尾のL」は、Lのあとに母音が来ない所（will、world、help）。「語頭のL」は母音の前（lights、leave）。
- 「短母音＋有声語尾」は、短い母音（ɪ ɛ æ ʌ ʊ）のあとに b d g v z dʒ ð で終わる語（bag、big、have、good）。
- 「子音の連続」は、語の中で子音が2つ以上続く所（world、first、climb）。日本語話者が母音をはさみやすい所。
- 地名と名前（Kenya、Finland、Peru、Hawaii、Haneda、Nairobi、Lulu）は、音声認識が外しやすいので**数えていない**。39音の数には入れた。
- 狙う音の土台：日本語話者の聞き取りやすさに効く音として、/æ f v θ ð w l r/ の8つが挙げられている（Saito の研究。確からしさ：有力）。依頼文の「語尾のL・F/V・TH・短母音＋有声語尾」を足した。

### セットS1：窓口「夢を言う」（案A）

After that, we will climb to an old village in Peru. And finally, I just wish to sit on a sunny beach in Hawaii. It is a very big dream.

意味の控え：30日かけて世界を一周します。何か月も考えてきました。まず、ケニアで野生の動物が自由に走るのを見たい。次に、フィンランドでオーロラが光るのを見ます。そのあと、ペルーの古い村まで登ります。最後に、ハワイの日の当たる浜辺にただ座りたい。とても大きな夢です。

## 3. 成果物3：弱点の集計仕様

### 3-1. 全体の形

```
[話す] → [単語の結果] → [音への割り当て] → [音ごとの記録] → [順位] → [鍛える音 上位3]
          方式①：聞き取り結果と紙の文の突き合わせ（今の analyze）
          方式②：Azure の単語・音ごとの点
```

方式①と②は「単語の結果」と「音への割り当て」だけが違い、そのあとは同じ。どちらも下の形の記録を出す。

```
{ snd:'th', word:'thirty', scene:'desk_dream', src:'ws'|'az', n:機会の重み, x:失敗の重み }
```

### 3-2. 音タグの辞書（作るときに1回だけ）

- tour-src で cmudict から、ゲームに出る全単語に音タグを付けて、発音記号（IPAC）と同じやり方でHTMLに入れる。実行時のAIはゼロ。
- タグは、いまの強化合宿の音（`SND`：f v th l r b sh s w ng end ae uh）に合わせ、足りない分を足す：語尾のL、ɚ、短いイ、有声の語尾、子音の連続、S＋イ。いまの `SND` の `l` は語頭と語尾を分けていないので、分ける。
- 読みが2つある語（read、live、close、use）は手で指定する表を持つ。

### 3-3. 方式①（ブラウザの音声認識）の数え方

単語の結果は、いまの `kindOf` の5種類をそのまま使う。

| 単語の結果 | 意味 | 音への割り当て |
|---|---|---|
| ok | 合った | その単語の全タグに 機会1・失敗0 |
| diff | 別の単語に聞こえた | 紙の単語と聞こえた単語の音を並べて比べ、**変わった音・消えた音のタグだけ**に 機会1・失敗1。残りのタグは 機会1・失敗0。聞こえた単語が辞書にないときは、全タグに 機会1・失敗0.5 |
| tail | 語尾が切れて聞こえた | 語尾のタグ（語尾のL、語尾の破裂音、有声の語尾）に 機会1・失敗1 |
| extra | 余分な音がついて聞こえた | 子音の連続・語尾のタグに 機会1・失敗1（母音をはさんだ疑い） |
| miss | 聞こえなかった | 全タグに 機会0.5・失敗0.25（発音より、タイミングの疑いが強いので軽く） |

足すこと2つ：

- **候補の2番目・3番目も見る。** いまも候補は3つ取っている（`maxAlternatives=3`）が、記録（`plogAdd`）に残るのは1つ。1番目が外れで2・3番目に紙の単語があれば「きわどい」として失敗を半分にする。
- **よくある聞こえ方の表**を持ち、当てはまれば失敗を確かにする：TH→s／t／z／d（think→sink）、V→b（very→berry）、F→h、L⇄R（light⇄right）、æ→ʌ・ɑ（bag→bug）、語尾の子音が消える、母音が足される。

### 3-4. 方式②（Azure 発音評価）の数え方

- 紙の文を `ReferenceText` に渡し、音ごとの点（0〜100）を取る。音の記号は Azure の出す形から、同じ音タグに直す。
- 音の点が低い → 失敗1、中くらい → 失敗0.5、高い → 失敗0。**境目の数字（例：60と80）は仮**。本人の録音で決める。
- 単語の種類が「抜けた（Omission）」「余分（Insertion）」のものは、発音でなく読み方の問題として、音の集計に入れない。
- 30秒をこえる音声は続けて流す方式が要る。3セットとも30〜45秒の見込みなので、続けて流すか、息つぎで分けて送る。
- Microsoft の回答でも、音ごとの点は「目安であって絶対ではない」とされている（正しく言った th に低い点が出る報告がある）。方式②でも、下の3-5の切り分けは同じように通す。

### 3-5. 誤認識（マイク・タイミング）と発音の切り分け

上から順にかける。どれも「疑わしいものは数えない／軽くする」方向。

1. **録音が成り立っているか。** 聞こえた語が紙の4割に満たない、または認識の自信の値が全体に低いときは、その回を集計に使わない。物語はそのまま進め、次の場面で測る。
2. **言い始めと言い終わり。** 最初の2語と最後の2語が聞こえていないのは、マイクの立ち上がり・切れの疑い。機会から外す。
3. **続けて3語以上の抜け。** 発音ではなく、止まった・聞き取りが切れた、と扱って外す。
4. **地名・名前・数字。** 数えない（数字は言い直しが合ったときだけ数える）。
5. **短いつなぎの語**（the、a、to、of、and、is、it）は弱く読むのが普通で、聞き違いも多い。重みを半分にする。
6. **同じ音を、別の単語で。** 「弱い」と決めるのは、別々の単語2つ以上で失敗したときだけ。1単語だけなら、その単語の問題かもしれない。
7. **別の場面でもう一度。** 案Aと案Cの両方で失敗が出た音 → 「鍛える音」。片方だけ → 「様子見」。
8. **全体に通らない人。** 全体の合った割合が5割未満のときは、どの音も弱く出る。順位は使うが「確定」にせず、旅の最初の2〜3場面の結果を足してから決める。
9. **「これでOK」を押した聞き違い**（`kanpe-homo-v1`）は、失敗に数えない。

### 3-6. 音ごとの記録と順位

- 記録：音ごとに、機会の合計 N、失敗の合計 X、失敗した単語の一覧、場面の数、最後に測った日。端末の中だけに置く（新しいキー。例 `kanpe-snd-v1`）。「はじめから」でも消さない（設計図の決めること6のクロ案と同じ。未決定）。
- 弱さ ＝（X＋0.5）÷（N＋2）。機会が少ない音が、たまたまの1回で上位に来ないようにするための足し算。
- 「鍛える音」に入る条件：機会3以上、別々の単語2つ以上で失敗、3-5の7を満たす。
- 順位：弱さの大きい順。同じなら、8つの音（æ f v θ ð w l r）を先にする。
- 出すもの：鍛える音＝上位3つ（1番目が主役）、様子見＝その次の3つ。
- 数字（0.5、2、3、上位3つ）はすべて仮。試作で動かして直す。

### 3-7. 精度について（分かること／推定／未確認）

**分かっていること（今回、実物で数えた・読んだ）**
- 3セットに入っている音と単語（第2章の表）。
- いまの冒頭の文には V が0語、TH は thank だけ。
- いまのゲームは、候補3つ・途中結果あり・1回ごとに切れる設定で聞いている。数字の言い直しは999まで。
- 方式①が返すのは「文字」と「自信の値」だけで、音ごとの点は出ない（Web Speech API の仕様）。
- Azure の発音評価は、音・音節・単語・全文の点を返し、基本の料金は音声認識と同じ扱い。追加料金の表に載っているのは、抑揚（prosody）などの上乗せ機能（Microsoft の説明ページと料金表の検索結果の抜粋で確認、2026-11-16。この作業場所からはページ本体を開けなかったので、**金額そのものは実装前に料金ページで見る**）。

**推定（理屈ではそうなるが、確かめていない）**
- 「別の単語に聞こえた」から弱い音を当てる方法は、推定。音声認識は文の流れから「ありそうな単語」に直して返すので、**弱い音でも通ってしまう（見逃す）方向**にずれやすい。逆に、めずらしい単語は発音が良くても外れやすい。
- 最初の1回（案A）は、声の小ささやマイクの立ち上がりで不安定になりやすい。
- 1回59〜76語で、狙う音ごとの単語は3〜8語。1回で決めるには少なく、2回＋旅の最初の数場面を足して決まる、という見込み。

**未確認（実機か本人の声がないと分からない）**
- 方式①の当たり具合そのもの。タスク002の基準（上位3つに、本人が自覚している音が2つ以上）で見る。
- スマホで30〜45秒を続けて聞けるか（Android の Chrome、iPhone の Safari）。切れたときの自動の聞き直しが、文のつなぎ目で語を落とさないか。
- Azure の音ごとの点の境目。

**確かめ方の案（試作のとき。合わせて10分ほど）**
1. 同じセットを2回読む → 上位3つのうち2つ以上が同じか（同じ結果がくり返し出るか）。
2. わざと th を s、v を b で読む → その音が上位に出るか（拾えるか）。
3. ていねいに読む → 弱い音が出すぎないか（出しすぎないか）。
4. 本人の自覚と比べる（タスク002の基準）。外れたら、文の音の配分を直すか、方式②と比べる。

## 4. 成果物4：鍛える場面への反映方法

### 4-0. 先に：今の会話のままでは、反映する先が足りない（実測）

tour-src/data.py の37会話で、キングが言う文を音タグで数えた。

| 音 | その音の単語が2つ以上ある会話 | 1つもない会話 |
|---|---|---|
| TH /θ/ | 5／37 | 2 |
| F | 11／37 | 7 |
| V | 9／37 | 14 |
| 語尾のL | 12／37 | 13 |
| R | 14／37 | 10 |
| SH | 0／37 | 29 |
| æ | 32／37 | 0 |
| 短母音＋有声語尾 | 24／37 | 4 |

「弱い音の単語が多い場面を選んで出す」だけでは、TH や V が弱い人に出せる場面がほとんどない。だから反映は、場面を選ぶ方法ではなく、**同じ場面の中で、言い方を選ぶ方法**（規則1）を中心にする。

### 4-1. 反映の規則

1. **言い分け。** 会話のキングの文に、同じ意味で言い方の違う候補を2〜3つ持たせる（data.py に足す）。鍛える音の単語が多い方を出す。例：入国審査で滞在日数を答える文は、「For three days.」（TH）／「I'll leave on Friday.」（L・V・F）／「Just a few days.」（F・ʌ）。決まり「同じ内容の質問でも同じ文章にしない」とも合う。選ぶのは辞書のタグの数え上げだけ。
2. **入れすぎない。** 1つの会話（5往復）で、鍛える音の単語は3〜5語、1文に2語まで。早口言葉にしない（不自然な水増しをしない決まり）。
3. **主役は1つ。** 鍛える音は上位3つまで。そのうち主役の音を、会話ごとに一番多くする。
4. **▶の分かれ目は、音で不利にしない。** 選択肢は意味で選ぶもの。どの選択肢にも、鍛える音の単語を1つずつ入れる（どれを選んでも出会う）。
5. **場面の語（1本に5つ）。** 候補の中から、鍛える音を含む語を最大2つ優先する。
6. **聞く側にも置く。** 相手のセリフ・アナウンス・看板に、鍛える音で意味が変わる組（light／right、bag／back、boat／vote など）を、聞き取らないと動けない形で置く（バイブル§3「音で束ねる」、§5のアナウンスイベント）。
7. **国の音と重ねる。** バイブル§3の「この国は /æ/ の音の国」を採るなら、国の音と本人の鍛える音が同じ国では、規則2の上限を1語ふやす。
8. **強化合宿。** いまの `pickLessons` は「言えなかった単語」から音を1つ選ぶ。入力を音ごとの記録（3-6）に替え、主役の音から始める。語尾のL・ɚ・短いイ・有声の語尾には、口の図が新しく要る（提案事項）。
9. **入れ替え。** 主役の音は、直近の機会10語で失敗2語以下になったら外し、様子見の1番目を上げる。あとで崩れたら戻す。数字は仮。
10. **測り直しは、物語の中で。** 「復習」も「再テスト」も作らない。まとまった文を言う場面を、旅の決まった所に置く。
    - **ルルの記録帳（声の日記）**：各国の出発ゲートで、その国であったことを2〜3文・40語ほどで言う。案Cで始めた「記録帳に声で書く」の続き。文には、その時の鍛える音の単語を規則1・2で入れる。
    - **最後の入国（羽田か成田）**：係官「Where have you been?」に、行った場所をまとまって答える。セットS1の過去の形（I saw wild animals run free in Kenya. …）。出発前に言った夢が、行ってきた話として戻る（バイブル§6「帰り道の鏡」）。最初と最後の比べは裏側だけで行い、画面には出さない。

### 4-2. プレイヤーへの見せ方（成績にしない）

| 案 | 見せ方 | 気をつける所 |
|---|---|---|
| ア | 何も見せない。出てくる言い方と、合宿の最初の音が変わるだけ | 一番安全。「最初の読み上げが効いている」とは気づかない |
| イ | 賢者の一言（タスク002の案）。窓口へ送り出すとき「Your TH will carry the stories of this trip.」のように、1つの音だけを旅の課題として渡す | 判定が外れていると、最初から間違った課題を渡す。2回測る前（賢者の時点）には言えないので、置くなら案Cのあと、ルルの一言にする |
| ウ | 星の地図。記録帳に星座があり、星1つが音1つ。場面でその音を通すたびに星が明るくなる。数字・％・順位は出さない。暗い星を「できない音」と呼ばず「まだ旅していない星」として置く | 星の明るさが点数に見えないよう、段階は2つ（灯る／まだ）だけにする |
| エ | 相手の聞き返し。鍛える音の単語が通らなかったとき、相手が「Sorry?」と聞き返す。言い直して通じたら相手が笑う | 現実の旅と同じ出来事になる。1つの会話で1回まで。今の「7割未満で止めない」決まりは変えない |

どれを採るかは **PM確認5**。組み合わせもできる（例：ア＋エ）。
