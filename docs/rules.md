# ルール（プロジェクト指示文＋キングの決定）

最終更新: 2026-11-16。ここに書いてあることは「決まったこと」です。聞き直さず、そのまま守ってください。変えるときは、作る前にキングに提案して確認を取ります。

## 1. このゲームは何か
- 空港を舞台にした、ピクセル風・ドラクエ風の英会話ゲーム「空港えいご物語」。グアム編・ドバイ編があり、世界マップでつながる。
- 目標は、暗記していると意識させずに、英語が話せる・聞けるようになること。一番避けたいのは、飽きて使わなくなること。
- 国を進むほど、ストーリー性・ゲーム性・難易度を少しずつ上げる。勉強している感覚はなるべく出さない。
- 旅行前のリハーサルになり、実際に行ったとき「ゲームで見た」と思える作りにする（広さ・空気感・お店の豆知識）。

- 頼まれていない日本語・説明・場所名・評価を画面に入れない。
- 「できました」と言うときは、見本と同じ指標で測った数字を添える。
- 実装前に実物のデータ（実際の画面・ファイルの中身）を確認する。想像で作らない。実機で確認できないことは「未確認」と明記する。
- 最後の点検で、お金の損失・健康情報の扱い・診断と誤解される表現・個人情報・権利を確認する。

- 自分で調べれば分かることを調べずに「未確認」と報告しない。手抜きは禁止。
- 回答は結論から先に述べる。

## 3. 画面とUIの決まりごと
- 場面の流れは「場所を選ぶ → すすむ → 相手 → カンペ → 単語バトル」。基本ベースは勝手に変えない。
- 単語バトルは、即答できる単語を卒業させる「選別装置」として使う（テストではない）。英単語→日本語3択の答え合わせは廃止の方向（`docs/pm/DECISIONS.md` 2026-11-15）。単語の確認は、場面の中で使うことと発音で行う。※いまの実物（Word Battle と、日本語で答え合わせをする Meaning!）は、置き換え先の設計が別途必要なため、**置き換えは別依頼**。それまで実物は今のまま動かす。
- スマホで文字を打つ入力は入れない。入力は発音か、英語の短文を選んで発音するだけ（2026-11-15）。
- NPCに近づいてタップして話を聞いて回る方式は入れない。イベントはプレイヤーの方に来る（2026-11-15）。
- 国に着いたときは「国旗＋その国の色＋ふざけた一言＋現地の挨拶」の1枚画面を出す（2026-11-15）。
- パスポートのスタンプは実物の流用をせず、形と要素だけ借りた自作にする（2026-11-15）。
- 場面の並びは、ルルが左・キングが右（グアムと統一）。
- 行き先が複数ある場所は、最初にドラクエ風の▶選択肢で選ばせる。▶の表示は世界マップの搭乗ゲートと同じ：1つの二重枠、▶は選んでいる行だけ点滅、最初は先頭が選択。選択画面は英文だけを出して読み上げ、日本語は足さない。
- 設定ボタンのある全画面と、グアム編にも🌏（世界マップ）ボタンを共通で表示する。
- カンペ画面：相手が言い終えたら自動で聞き始める。ボタンは「おてほん」と「もういちど」を同じ幅にする（スマホで親指が届くため）。
- 間違った語は赤でなく青で示す（赤と緑が同じに見えるため）。波線の下線は使わない。
- 場所名の看板文字は大きく。文字の余白・詰まり・絵との重なりに気をつける（小さい画面でも確認する）。
- 見た目はピクセル風。グラデーションのある白っぽい表現は使わない。ドット画は雑にせず、登場キャラの顔は今のゲームの絵と揃える。
- 地図の色味は暗すぎず明るくする。
- 国が変わってもUIや仕組みを変えない（英語が苦手な人が混乱するため）。変えるときは作る前に提案して確認。

## 4. 音と演出
- 各空港・場面に、その場に合った音楽・音をつける。ショーなどイベントには必ず音楽をつける。
- 背景音はグアムくらい静かに。シャカシャカした高い音は使わない。音楽は現地らしいもの。
- 発音が7割未満なら「ブッ」というエラー音、会話を全部言い終えたらドラクエ風のクリア音を鳴らす。

## 5. 場面づくり
- お店・ホテル・バー・番組名は常に実名にする。値段は架空でよい。個人名は入れない。同名の店が複数あるときは場面に近い場所でよい。
- 空港ごとに、スタッフの口調や接し方など雰囲気を変え、「どの空港も同じ」にしない。
- 空港には服装・人種の多様な人を出す。服装だけで悪役にしない。
- 会話は創作でふくらませ、1本5往復ほど。会話が続いてキャッチボールできる形にし、同じ場所に来るたび別の人と会話できるようにする。
- お店は道ではなく店内に入り、入るたびに客と会話が変わる形にする。
- 到着した国の現地時刻に、画面の時刻・昼夜を切り替える。
- 解放の順番や予約のような仕組みは、国ごとに最初に提案して確認する。

## 6. 発音と強化合宿
- 発音は「筋トレ」と捉える：口の筋肉を使って動かせば覚える。知識として教えるものではない。このゲームの目的は勉強から脱し、子どものように楽しんで旅をすること（2026-11-16）。
- 発音チェックは7割以上でOK。7割未満でも会話を止めず、言えなかった単語は記録に溜める。苦手の集計は、本人の実際の発音結果から行う。
- 強化合宿はルルが担当する。言えなかった単語に関連するフォニックスを先に学び、できるまで単語→文章と進める。
- フォニックスは「言えなかった単語」から苦手な音を選んで出す（Fに固定しない）。
- ルルが幼稚園児に教えるように、リズムで楽しく声で誘導する。口の図は補助で、英語と日本語の口を並べて比べる。
- 音声認識が聞き違える語（例：lulu を hello と聞く）は、不合格のとき「これでOK」ボタンで通せる。押した聞き違いは端末に記録され、次回から自動で合格になる。

## 7. 作るときの技術の決まりごと
- 本体はこのリポジトリ（`kingtheQ/kanpe-sensei-dubai`）の単一HTMLファイル。公開は `main` への push で GitHub Pages に反映される（`.github/workflows/pages.yml`）。
- 国ごとのデータは別ファイルに分ける方針（ドバイから試作）。
- マイクは音声認識の標準機能を使う。実機ごとに挙動が違うため、実機で確認できるまで「未確認」と伝える。
- 動作確認はヘッドレスブラウザで行う。ただしマイクの確認は実機が必要。
- 公開ページ（`kingtheq.github.io`）はクロの WebFetch では開けないことがあるため、リポジトリを手元で動かして確認する。

## 9. 世界一周編「KING & LULU WORLD JOURNEY」の決まり（2026-11-11〜14 にキングが決めたこと）
- プロジェクト名は「KING & LULU WORLD JOURNEY」（世界一周航空券を使った英語学習RPG）。主人公キング（英語が苦手）、相棒ルル（英語が得意なロボット。2026-11-16 時点でキングの前提。ゲームの中の言葉にはまだ出していない）、期間は約1か月、最後は羽田か成田に帰国し、思い出写真を見てなごむアニメーションで終わる。この基本設定は変えない。
- 最大の特徴は「空港が冒険の主役」。全体のボリュームは空港体験50％、観光・ホテル・移動など50％。空港ごとに同じイベントをくり返さず、規模・国・文化に応じて変える。
- ルートは収集済みの航空券ルール・口コミに基づき、券のルールに反する移動を選択肢に出さない。一本道にせず、各都市でキングが選べる行動と分岐を置く。
- 30日間で5000語を各日・各ステージに配分し、発音練習を必ず入れる。語のくり返しは、物語の必然の中で起こす（「復習」という言葉・画面は入れない。2026-11-15）。不自然な水増しはしない。
- 何度でも遊べるようにする。別の世界一周航空券（ルールセット）を選ぶと別ルート・別の空港を体験でき、キングとルルは共通の主人公として旅ごとに思い出が増えていく。
- すでに作ったもの（冒頭3場面）は作り直さない。最初から細かい仕様を決めず、まず全体像を見てから一緒に調整する。大量の質問で作業を止めない。
- 始まりの役割分担：賢者は心構えと、あとで失敗しないための助言。チケット売り場は、キングたちの希望（行きたい場所）を細かく聞き取り、「この券がおすすめ」とすすめ、券を買う流れを通して世界一周航空券のルールを詳しく知れる始まりにする。行きたい国・場所は自分で選べる形（行き先が固定で選べないのは意図とちがう）。
- 窓口の聞き取りは、「旅のしかた」で券が決まる12種類（素材集の早見表）を係員の質問にして、答えで券が決まる形で進める（キングが「はい」と答えた）。
- 行ける51空港から、2周目・3周目と重なってもよいなら4周目まで遊べる。最終的には51か所（素材集の行ける空港・国）を全部作る絵を想像している。
- 広告のキャッチは案1「100万円の世界一周航空券、まずゲームで買ってみた。」に決定（主役を英語でなく世界一周にする）。
- 単語の選び方：同じ内容の質問でも同じ文章にしない。国によって入国審査員の対応は親切から不愛想まで違い、空港で迷うこともしょっちゅうなので、「困った時に聞ける・伝えることができる・聞き取れる」場面展開にする。相手の性格で言い分ける・困った場面を増やす・単語バトルの選び方に決まりを作る、でOK。
- 国の人柄・国柄を会話に反映する（例：ニューヨークの人は早口でせっかち）。ただし、進むほどどんどん冷たくなっていくのは望まない。
- 空港ごとの話し方（国柄）の調査は51空港すべてを対象にする（時間がかかってもよい）。
- 空港の素材収集は、2周目（リスボン・アテネまで）でリサーチをしめ、ゲームの組み立てに入る（2026-11-14決定）。3周目15空港・4周目8空港は、作る順が近づいたら調べる。素材集のルール：資料で数字が割れたら両方書く、お店は作る直前に確かめ直す、書きこんだら件数・確認レベル別の数(A・B・C)・出典ページ数を報告する。
- ゲームの組み立ては1周目→2周目の順。1周目の入り方は「A 流れを1周つなぐ（トップ→世界マップ⇄世界一周編→ナイロビ出発・機内→次の空港の到着）」を先にする（窓口の聞き取りはそのあと）。ナイロビの次につなぐ空港は、聞き取りを作るまでの仮の1本としてドーハ（oneworld）。世界マップから世界一周編への入口は「案1 地図に？を足す（羽田の搭乗ゲートで西の？？の国を選ぶ、新しいボタンは足さない）」。
- 到着と出発の画面では、最初の場所をクリアしないと次の場所ができないようにする（順番に開く）。国をクリアしたら、その国のマップに戻さず世界マップに戻す。券を買ったあとのナイロビに賢者（チケットを買う場面）が出るのはおかしい。会話の中で「東京へ行く」と言わせない（東京に戻ってしまうため）。
- グアム編は、ドバイ編に合わせる（設定画面・発音画面の文字の色・「はなす」を押さなくても自動で聞き始める・強化合宿の行き先）。ゲーム途中で設定を切りかえたら、その場の画面にすぐ反映する。強化合宿は長すぎて疲れるのでコンパクトに。
- 世界マップの上の枠（いまの ばしょ）は、枠なし・マットな薄い黄色・黒文字にして、下の選ぶ枠（2本線）と見分けられるようにする。案内の文字は小さすぎないように。
- ドバイは必ず寄る場所でなく「隠しイベント」（会話3つの場所の3つ目などでヒント券がもらえ、何か所かで当たると行ける）。ドバイでUI・作り・構成を固め、同じパターンで他の国をざっと作ってから、国の特徴や体験で色づけする。
- クリア条件：1か所に会話が3つあっても1つクリアできれば次へ進める。日本に帰ればゴール。
- イベントはその国で実際にあった事例に基づける（失敗体験、お金の引き出し、空港での苦労、突発事件で一時帰国など）。乗る飛行機の機種ごとに見た目・居心地を変えたい。手抜きで飽きるゲームにしない。
- お金は最後に集計発表し、途中経過はルルのカバンの記録帳として設定から細かく見られるようにする。
- 世界一周航空券はビジネスクラスがいい（疲れにくい・ラウンジが使える）。金額やルールはできるかぎりリアルにしたい。
- 約1か月（1日＝旅の1日）の版を候補にしている。チケットの型（スター型/oneworld型）は行きたい場所で決まるのか悩んでいて、未決。
- 世界一周で行きたいのは、HISなどでは行きづらい・高い・遠い場所（アフリカ、オーロラ、など）と、船の世界一周では行けない場所。アジアは気軽に行けるので優先しない。
- 世界一周の達人賢者がチケット決め・場所決めの前に登場し、ゲーム途中で「あの国のチケットにすればよかった」と後悔しないよう助言する。実際の世界一周航空券サイトの助言・おすすめ・注意事項も素材に加える。
- 夢は世界2周（1周は世界一周航空券、もう1周は船の旅）。船旅は飛行機の旅が終わった後の続編として構想している（運河・イースター島・タヒチなどは船のために残す）。
